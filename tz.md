# Техническое задание: личный планировщик покупок

Версия ТЗ: 1.3. Дата: 13 октября 2026 года. Версия схемы данных остаётся 1.

## 1. Назначение и приоритет требований

Создать русскоязычное веб-приложение для подготовки списка покупок, использования в магазине и переноса некупленных товаров на следующий поход. Основное устройство — телефон. Приложение открывается по ссылке в браузере и после первой успешной подготовки работает при повторном открытии без интернета.

Это ТЗ — основной документ для реализации. При расхождении с `concept.md` использовать это ТЗ: после концепции пользователь уточнил, что текущий поход только один, история доступна только для просмотра, количество состоит из числа и единицы, одинаковые товары объединяются, а дополнительные файлы для офлайн-работы разрешены.

Технические детали и пограничные случаи, не заданные пользователем напрямую, определены в этом документе как решения первой версии. Реализовать их без расширения функциональности. На текущем этапе создаётся только ТЗ, а не код приложения.

## 2. Пользователи и границы продукта

Единственная роль — владелец локальных данных в браузере. Он может управлять текущим походом, отмечать покупки, использовать каталог названий, просматривать и удалять историю. Регистрации, авторизации, администратора, совместного доступа и разграничения прав нет.

Все покупки и каталог хранятся исключительно в `localStorage`. Кэш браузера хранит файлы приложения для офлайн-запуска, а не покупки. Отсутствуют серверная логика, база данных, облачная синхронизация, аналитика и передача пользовательского содержимого по сети. Статический HTTPS-хостинг нужен только для выдачи файлов страницы.

Не включать в первую версию: цены, бюджет, категории, комментарии, напоминания, фотографии, штрихкоды, выбор магазина, несколько текущих походов, тёмную тему, экспорт/импорт, автоматическое завершение, перенос в существующий поход и выбор отдельных товаров при переносе.

## 3. Состав реализации и запуск

Использовать обычные HTML, CSS и JavaScript без фреймворков, пакетного менеджера и сборки. Все зависимости и ресурсы локальные; CDN, внешние шрифты и удалённые иконки запрещены.

| Файл | Назначение |
| --- | --- |
| `index.html` | Семантическая разметка, подключение стилей, скрипта и манифеста |
| `style.css` | Все стили и адаптивность |
| `script.js` | Данные, интерфейс, валидация, действия и регистрация service worker |
| `sw.js` | Кэширование файлов, офлайн-запуск, управление версиями кэша |
| `manifest.webmanifest` | Название, относительные start_url и scope, standalone, цвета и иконки |
| `icons/icon-192.png` | Локальная иконка 192 × 192 |
| `icons/icon-512.png` | Локальная иконка 512 × 512 |
| `README.md` | Инструкция размещения, запуска и проверки офлайн-режима |

Основные файлы остаются HTML, CSS и JS; дополнительные файлы разрешены пользователем для повторного открытия без интернета. Манифест и иконки позволяют использовать добавление на главный экран. Добавить ненавязчивую кнопку установки там, где браузер предоставляет такую возможность, и справку о ручном добавлении на главный экран; точные правила — в разделе 12.1. Установка не обязательна для офлайн-работы; одинаковый механизм установки на всех телефонах не обещать.

Размещать все файлы на одном статическом HTTPS-хостинге. Поддерживать корень сайта и подпапку через относительные пути. Для разработки допустим localhost. Открытие `index.html` как `file://` не является основным способом запуска и не проходит приёмку офлайн-режима; при таком запуске показать пояснение о необходимости HTTPS-ссылки или localhost.

В `README.md` описать передачу всех файлов на любой статический HTTPS-хостинг без выбора платного провайдера и без необходимости backend. Публикация сайта не входит в написание кода: результат должен быть готов к размещению.

## 4. Навигация и состояния страницы

Одна страница с тремя разделами: «Текущий поход», «Каталог», «История». Переключение разделов не перезагружает страницу и не требует сетевых запросов. После открытия всегда показывать «Текущий поход».

### 4.1. Текущий поход

Если похода нет: текст «Текущего похода пока нет» и кнопка «Создать поход». Не создавать пустой поход автоматически.

Если поход есть, показывать:

- Название и дату; действие «Изменить поход».
- Счётчик «Куплено X из Y», где считаются строки товаров, а не сумма количества.
- Форму добавления: название, количество, единица и «Добавить».
- Фильтры «Все», «Осталось», «Куплено». По умолчанию «Все».
- Список товаров с отметками и действиями редактирования/удаления.
- Кнопки «Перенести некупленное», «Завершить поход», «Удалить поход».

Кнопки завершения и удаления визуально отделить от повседневных действий. Кнопка переноса недоступна при отсутствии некупленных товаров. Кнопка создания второго текущего похода отсутствует.

Пустой поход: «Добавьте первую покупку». Пустой фильтр «Осталось»: «Всё куплено». Пустой фильтр «Куплено»: «Пока ничего не куплено». Счётчик всегда учитывает весь поход, независимо от фильтра.

### 4.2. Каталог

Поиск по названию, список сохранённых названий по русскому алфавиту, действия «Добавить в поход» и «Удалить из каталога». Для пустого каталога пояснить, что названия появятся после добавления товаров. При пустом результате поиска показать «Ничего не найдено».

Если текущего похода нет, действие добавления из каталога открывает создание похода. После успешного создания открывается форма добавления выбранного товара; если пользователь отменит эту форму, созданный пустой поход остаётся. Сам товар без подтверждения не добавляется.

### 4.3. История

Список завершённых походов, новые сверху по времени завершения; при равенстве — по времени создания, затем по ID. Карточка содержит название, плановую дату и текущий счётчик купленного в архиве. Можно открыть детали и удалить поход с подтверждением.

Детали истории: название, дата, время завершения, все товары, их количества и статусы. Купленные вычёркнуты. Доступны фильтры и счётчик; добавление, изменение, отметка покупки, перенос и повторное открытие в качестве текущего похода отсутствуют.

При переносе архив исходного похода содержит только оставшиеся купленные товары. Показать пояснение «Некупленные товары перенесены в следующий поход» и количество перенесённых строк. Не восстанавливать перемещённые строки в истории: перенос означает перемещение, а не копирование.

В разделе есть действие «Очистить историю» с подтверждением. Оно удаляет только завершённые походы; текущий поход и каталог сохраняются. Пустая история: «Завершённые походы появятся здесь».

Внизу раздела показывать число завершённых походов и приблизительный размер всех данных приложения. При большом размере предлагать вручную удалить старые походы или ненужные названия каталога. Не ограничивать историю числом 50 и не удалять старые походы автоматически. Точные правила предупреждения и обработки переполнения — в разделе 11.2.

## 5. Правила походов

### 5.1. Создание

Поля формы: название и дата. Дата по умолчанию — сегодняшняя локальная календарная дата устройства. Название по умолчанию — «Покупки — ДД.ММ.ГГГГ». По уточнению пользователя при смене даты автоматическое название тоже меняется. Собственное название не переписывать: обновлять поле только пока оно совпадает с последним предложенным автоматическим названием. Это правило действует при создании, переносе и редактировании похода; при редактировании автосвязь включена, если исходное название соответствует его текущей дате. Пустая или недопустимая дата не обновляет название. До подтверждения формы меняется только черновик.

Название: после обрезки краёв и свёртки повторных пробелов от 1 до 80 символов. Дата обязательна, реальная календарная дата в диапазоне 1900–2100 включительно; прошедшие даты разрешены. Дата — план похода, она не завершает поход автоматически.

«Создать» сохраняет пустой текущий поход и открывает его. «Отмена» ничего не меняет. При существующем текущем походе создание нового запрещено также на уровне логики, включая устаревшую форму в другой вкладке.

### 5.2. Изменение

Только текущий поход: изменить название и дату по тем же правилам. Товары и статусы не меняются. ID и время создания сохраняются.

### 5.3. Завершение без переноса

Отдельное действие «Завершить поход» открывает подтверждение. Если остались покупки: «Осталось N товаров. Они останутся в истории; перенести их после завершения нельзя». В диалоге предложить «Перенести некупленное» как альтернативу, «Завершить без переноса» и «Отмена». Альтернатива открывает форму переноса и не завершает поход до её подтверждения.

После завершения все строки остаются в архиве со своими статусами, текущего похода нет. Автоматически новый поход не создаётся. Пустой поход также разрешено завершить с подтверждением.

### 5.4. Удаление

Удаление текущего или архивного похода требует подтверждения с его названием и предупреждением об удалении всех его товаров. Каталог названий сохраняется. Удаление текущего похода освобождает возможность создать новый. Отмена не меняет данные. Удаление похода и очистка истории не имеют кратковременной отмены после подтверждения.

## 6. Товары: ввод, объединение, отметки

### 6.1. Поля и нормализация

Название обязательно, 1–100 символов после нормализации: Unicode NFC, обрезка краёв, все последовательности пробельных символов заменить одним пробелом. Для сравнения названий дополнительно применять русское приведение к нижнему регистру. «Молоко» и «  молоко » — одно название; «е» и «ё» остаются разными; знаки препинания не удалять.

Количество: положительное число от 0,001 до 999999,999 включительно, до трёх знаков после запятой. Принимать запятую или точку; не принимать знак минус, экспоненциальную запись, смешанные разделители, пустое поле, NaN и Infinity. Поле по умолчанию — 1. Превышение точности отклонять, а не округлять молча.

Единица выбирается только из списка: «шт.», «кг», «г», «л», «мл», «уп.». По умолчанию «шт.». Свободные единицы и преобразование кг в г или л в мл отсутствуют. Дробное количество разрешено для любой единицы.

По последующему уточнению пользователя количество можно менять кнопками ▲/▼ внутри общей рамки поля, справа от числового ввода, а также клавишами ArrowUp/ArrowDown. Шаг — 1 с сохранением дробной части. Если следующий шаг выходит за допустимые границы, число остаётся прежним; более мелкие изменения доступны ручным вводом. Кнопки действуют в обеих формах, не отправляют форму и не сохраняют черновик до подтверждения. Размер области нажатия каждой кнопки — не меньше 44 × 44 px.

Ошибки показывать у соответствующих полей; форма остаётся открытой, введённые значения сохраняются. При успешном добавлении очистить название, вернуть количество 1 и единицу «шт.», поставить фокус в название. Enter отправляет форму, если пользователь не выбирает подсказку.

### 6.2. Добавление и дубликаты

В одном походе уникальна пара «нормализованное название + единица». Одинаковое название с разными единицами образует разные строки. Каталог при этом содержит одно название.

Если совпадения нет — создать строку с новым ID и `purchased: false`, добавить в конец порядка добавления.

Если совпадение есть — увеличить его количество на введённое, снять отметку покупки, сохранить ID, написание названия и положение существующей строки. Сообщить «Количество увеличено». При сумме выше допустимого максимума отклонить всю операцию; не менять ни товар, ни каталог. Складывать через целые тысячные, чтобы избежать ошибок десятичной арифметики.

Повторный быстрый клик по кнопке одной отправки не должен дважды добавлять товар. После сохранения показывать актуальный список.

### 6.3. Редактирование

Для текущего похода открыть форму с текущими названием, числом и единицей. Сохранение заменяет поля строки; отметка покупки остаётся прежней. Новое название автоматически попадает в каталог; старое из каталога автоматически не удаляется.

Если результат редактирования совпадает с другой строкой, до сохранения показать предложение объединить. Подтверждение складывает новое количество редактируемой строки с количеством строки назначения; исходная строка удаляется, ID/написание/порядок строки назначения сохраняются. Итоговая отметка покупки снимается. При превышении максимума объединение запрещено. Отмена объединения возвращает к форме без изменения данных.

### 6.4. Покупка и порядок

Нажатие на чекбокс или область названия текущего товара переключает `purchased`. Кнопки редактирования и удаления не переключают отметку. Купленное название вычёркнуто, чекбокс отмечен, вторичный текст менее контрастен, но читаем.

В режиме «Все» сначала некупленные, затем купленные. В каждой группе сохраняется порядок добавления. При снятии отметки товар возвращается к своему исходному месту среди некупленных. В активном фильтре строка, переставшая ему соответствовать, исчезает сразу. Отметить всё одной кнопкой нельзя.

### 6.5. Удаление товара и отмена

Удаление строки текущего похода выполняется сразу. Показать сообщение «Товар удалён» с кнопкой «Отменить» на 10 секунд. Отмена восстанавливает всю строку с прежними ID, количеством, отметкой и порядком. Не показывать обратный отсчёт каждую секунду.

Хранить только последнюю отменяемую операцию в памяти. Любое следующее успешное изменение данных, включая удаление другого товара, завершение/перенос, создание или изменение каталога, отменяет предыдущую возможность восстановления. Смена фильтра/раздела не отменяет её. Перезагрузка, закрытие страницы и внешнее изменение в другой вкладке отменяют её. Неудачная запись данных не удаляет строку и не запускает таймер. Каталог при удалении товара сохраняется.

Реализацию ограничить одной записью для восстановления и одним таймером: не заводить отдельные таймеры для строк, не сбрасывать таймер при переключении разделов. При внешнем изменении выключить отмену и перейти к защитному состоянию раздела 11.1. Корзина удалённых товаров и подтверждение каждого удаления не нужны.

## 7. Перенос на следующий поход

Перенос доступен только из текущего похода и при наличии хотя бы одной некупленной строки. Открыть форму нового названия и даты с теми же значениями по умолчанию и валидацией, что при создании. Показать число переносимых строк и текст о завершении исходного похода.

Подтверждение выполняет одну операцию сохранения:

1. Переместить все `purchased: false` из исходного похода в новый, сохранив название, количество, единицу, ID и взаимный порядок; перенумеровать порядок в новом походе от 0.
2. Оставить в исходном походе только купленные строки и их отметки.
3. Завершить исходный поход; записать время завершения и число перенесённых строк.
4. Создать новый поход с новым ID, статусом текущего и полями формы; открыть его с фильтром «Все».

Не завершать исходный поход до подтверждения. Отмена формы ничего не меняет. Если ничего не куплено, исходный поход попадёт в историю пустым с пояснением о переносе. Каталог не меняется. Кнопка защищена от повторной отправки. При ошибке сохранения ни один этап не применяется: исходный список остаётся текущим, новый отсутствует.

Чтобы оставить покупки в текущем списке до следующего посещения магазина, достаточно не нажимать завершение или перенос. Смена даты сама по себе ничего не переносит. При переносе пользователь не выбирает отдельные строки: ненужное предварительно удаляет.

## 8. Каталог и подсказки

Любое успешное добавление/редактирование товара автоматически добавляет его нормализованное название в каталог, если такого ещё нет. Каталог не содержит количества, единицы, отметки покупки или счётчика популярности. Для повторного названия сохранять первое написание. Предзаполненных товаров и демонстрационных походов нет.

Подсказки появляются при вводе хотя бы одного символа. Поиск — совпадение подстроки в нормализованном названии без учёта регистра. Порядок — алфавитный, максимум 8 подсказок. Подсказка заполняет только название; число и единица в форме сохраняются. Ничего не добавлять до подтверждения формы. Клавиши вверх/вниз выбирают подсказку, Enter подтверждает выбор, Escape закрывает список. Без выбранной подсказки Enter отправляет форму. Клик вне списка закрывает подсказки.

В отдельном каталоге поиск по тем же правилам без ограничения в 8 результатов. «Добавить в поход» открывает форму с названием, количеством 1 и единицей «шт.» и переводит в текущий поход. Повторное добавление подчиняется правилам объединения.

Удаление названия из каталога требует подтверждения. Товары в походах и истории не меняются. Удалённое название не восстанавливать при загрузке страницы, переносе, покупке или просмотре истории. Оно появится снова при новом успешном добавлении/сохранении редактирования товара с этим названием. Массовая очистка каталога, переименование его записей и избранное не нужны.

## 10. Структура данных и инварианты

Один ключ `localStorage`: `shopping-planner.state.v1`. Значение — один JSON-документ. Все связанные изменения писать одним `setItem`, чтобы не сохранить половину переноса. Ключи других приложений не затрагивать.

Пример схемы (техническая спецификация, не демонстрационные данные для пользователя):

```json
{
  "schemaVersion": 1,
  "revision": 1,
  "updatedAt": "2026-10-13T09:00:00.000Z",
  "trips": [
    {
      "id": "unique-trip-id",
      "name": "Покупки — 13.10.2026",
      "date": "2026-10-13",
      "status": "active",
      "createdAt": "2026-10-13T09:00:00.000Z",
      "updatedAt": "2026-10-13T09:00:00.000Z",
      "completedAt": null,
      "completionReason": null,
      "transferredItemCount": 0,
      "items": [
        {
          "id": "unique-item-id",
          "name": "Молоко",
          "quantity": 1.5,
          "unit": "л",
          "purchased": false,
          "order": 0
        }
      ]
    }
  ],
  "catalog": [
    { "id": "unique-catalog-id", "name": "Молоко" }
  ]
}
```

- Статус похода только `active` или `completed`; текущих походов не более одного. Отдельный activeTripId не хранить: вычислять по статусу.
- Массивы `trips`, `items` и `catalog` сохранять в указанном формате. Для ускорения работы разрешены вычисляемые `Map` по ID, индекс названий и ссылка на текущий поход в памяти; перестраивать их после загрузки и успешного изменения. Не сериализовать эти индексы и не добавлять дублирующий activeTripId в JSON.
- ID генерировать через `crypto.randomUUID()` с совместимым случайным резервным способом при отсутствии API; не использовать название или индекс массива как ID. ID уникальны внутри соответствующих сущностей; ID товара при перемещении сохраняется.
- `revision` — неотрицательное целое; увеличивается на 1 при каждой успешной записи; начальное пустое состояние имеет 0. Метки времени — ISO UTC; даты походов — `YYYY-MM-DD` без часового пояса. В интерфейсе даты и время отображаются локально по `ru-RU`; сегодняшнюю дату не получать через UTC-срез `toISOString()`.
- `completionReason` — null для текущего, `manual` или `transfer` для завершённого. `completedAt` обязателен для завершённого, null для текущего. `transferredItemCount` — целое, 0 при ручном завершении, больше 0 при переносе. Ссылку на следующий поход не хранить: его удаление не должно нарушать архив.
- `order` — уникальное неотрицательное целое внутри похода. Новая строка получает max(order) + 1; после удаления перенумерация не обязательна. При переносе назначить последовательность от 0.
- Количество хранить числом с точностью до тысячных; для операций переводить в целые тысячные. В UI десятичный разделитель — запятая, без лишних конечных нулей.
- Не хранить производные счётчики, нормализованные ключи названий и отсортированные копии: вычислять из основных данных.
- Раздел, поисковый запрос, фильтр, черновики форм и временная отмена удаления живут в памяти. После запуска текущий раздел и фильтр «Все», поиск пустой.
- Отсутствие ключа означает чистый первый запуск. Пустая строка, null внутри JSON, неверные типы, неверные поля/инварианты, дубли ID или названий каталога и неизвестная версия означают ошибку данных, а не первый запуск.

## 11. Сохранение и ошибки

При запуске: прочитать ключ, разобрать JSON, проверить версию через механизм раздела 11.3, затем проверить схему, все поля и инварианты. Для первого запуска проверить возможность записи/удаления собственного временного ключа; не вызывать `localStorage.clear()`.

Каждое действие: проверить актуальные данные и доступность действия, построить новую копию состояния, валидировать, сериализовать и записать; только после успешной записи заменить состояние в памяти и перерисовать интерфейс. При ошибке оставить старое состояние, сохранить черновик формы, показать «Не удалось сохранить изменения. Проверьте доступ к хранилищу браузера или свободное место». Не продолжать накопление изменений только в памяти под видом сохранения. Повторная попытка разрешена.

Повреждённые/неизвестной версии данные: заблокировать изменения и показать «Не удалось прочитать сохранённые данные». Действия «Попробовать снова» и «Сбросить данные». Сброс требует отдельного подтверждения «Все походы и каталог будут удалены без восстановления» и удаляет только собственный ключ. Автоматического исправления, обрезки истории или очистки данных не делать. Кэш файлов при сбросе пользовательских данных сохраняется.

При недоступном чтении хранилища показать ошибку и «Попробовать снова», не создавать молча пустое состояние. При недоступной записи существующие корректные данные можно просматривать; действия изменения не должны сообщать об успехе.

### 11.1. Несколько вкладок

Бесшовная синхронизация не требуется. Слушать `storage` только для собственного ключа и при внешнем изменении/удалении ключа, а также внешнем `clear`, сравнивать актуальную строку с загруженной. Если они различаются, не перестраивать интерфейс автоматически: прекратить возможность изменения данных и показать блокирующее сообщение «Данные изменены в другой вкладке. Обновите данные, чтобы продолжить» с кнопкой «Обновить данные». Отмену удаления выключить; черновик оставить в памяти до явного обновления, без возможности его отправить.

Перед каждой записью синхронно сравнивать актуальное значение ключа с исходной строкой, загруженной этой вкладкой (null для отсутствующего ключа). При расхождении ничего не записывать и показывать то же блокирующее сообщение. Сверять всю строку, а не только revision: сброс мог начать нумерацию заново. Между проверкой и записью не должно быть асинхронных операций.

Кнопка «Обновить данные» явно перечитывает, проверяет и загружает актуальное состояние; перед нажатием показать, что несохранённый ввод будет отброшен. Закрыть прежние формы, очистить отмену, перейти в текущий раздел с фильтром «Все». Если ключ удалён — показать первый запуск; если повреждён — защитный экран ошибки; если чтение недоступно — сообщение об ошибке и возможность повтора. После успешного обновления разрешить действия. Полноценная транзакционная координация действительно одновременных записей не требуется.

### 11.2. Размер данных и переполнение

У localStorage ограничен объём, а число походов не определяет размер записей. Не вводить автоматическое удаление истории и не показывать выдуманный процент свободного места.

В истории показывать «Походов в истории: N» и «Размер данных: примерно X КиБ» для всего JSON, включая текущий поход и каталог. Для единообразной приблизительной оценки использовать `2 * (имя_ключа.length + сериализованный_JSON.length)` байт и делить на 1024; показывать один десятичный знак. Это оценка объёма UTF-16-строк, а не измерение фактической квоты браузера. Для отсутствующего ключа размер — 0. Расчёт выполнять при загрузке и после успешного сохранения, без опроса по таймеру и без пробных записей для поиска лимита.

При оценке не менее 2 МиБ показывать постоянное предупреждение «Данных стало много. Чтобы снизить риск ошибки сохранения, удалите ненужные походы из истории или названия из каталога». Порог — ранний ориентир, не гарантированный предел; достижение порога не блокирует сохранение. Предложить переходы «Открыть историю» и «Открыть каталог». Автоматической очистки нет.

При `QuotaExceededError` оставить предыдущее состояние и черновик, показать отдельное сообщение «В хранилище браузера не хватает места. Удалите ненужные походы или названия из каталога и повторите действие». Оставить доступными просмотр и операции удаления/очистки с обычными подтверждениями; их запись тоже проверяется на успех. Не отключать все изменения навсегда: пользователь должен иметь возможность освободить место. Черновик добавления/редактирования сохранять при переходе к очистке; при удалении похода, к которому он относится, отбросить его. Не обещать, что предупреждение сработает до любой ошибки: хранилище источника сайта может использоваться другими страницами или быть недоступным.

`navigator.storage.estimate()` не использовать как процент заполненности localStorage: оценка общего хранилища источника не является точной квотой этого ключа. После ручного уменьшения данных пересчитать размер и убрать предупреждение, если оценка стала ниже порога. Кэш файлов приложения не включать в этот индикатор.

### 11.3. Версия схемы и будущие миграции

Версия ТЗ и версия схемы независимы. В первой реализации `CURRENT_SCHEMA_VERSION = 1`; включить отдельную функцию `migrateState(parsedState)`, которая возвращает `{ state, migrated }`. Для корректной версии 1 вернуть исходные данные с `migrated: false`, не записывая их повторно. Не создавать пустую функцию, которая молча принимает любую версию, и не реализовывать вымышленную схему 2.

Внутри предусмотреть реестр последовательных преобразований «версия N → N+1». Сейчас реестр пуст. При будущем повышении версии разработчик обязан добавить преобразование, валидатор исходной схемы и тесты. Если версия данных выше поддерживаемой, ниже поддерживаемой без полной цепочки преобразований, отсутствует или некорректна — показать защитную ошибку, не перезаписывать запись.

Контракт будущей миграции:

1. Работать с копией разобранных данных; проверить старую схему до первого шага и результат каждого шага. Не удалять походы, товары, каталог и не менять их смысл; сохранять ID, количества и статусы, если новая схема не требует явно описанного преобразования.
2. Применить все шаги в памяти, без промежуточных записей. Проверить итоговую схему и инварианты.
3. Перед финальной записью убедиться, что исходная строка в localStorage не изменилась; при расхождении действовать по разделу 11.1.
4. Только после успеха записать итог одним `setItem` в тот же стабильный ключ, увеличить revision один раз и обновить updatedAt. Суффикс `.v1` существующего ключа — историческое имя, не менять его автоматически вслед за schemaVersion; текущую схему определять по полю JSON.
5. При исключении, неверном результате, нехватке места или неизвестном шаге оставить исходную строку без изменений и показать ошибку обновления данных с повтором. Не запускать интерфейс редактирования на частично преобразованном состоянии.

Миграция должна быть повторяемой: после успешного обновления следующий запуск только читает новую схему и не переносит/не дублирует данные второй раз. Для первой версии проверять обработку текущей, некорректной и неподдерживаемой версии; тесты преобразования 1 → 2 обязательны только когда эта схема действительно появится.

## 12. Офлайн-работа и обновление файлов

Обязательный сценарий: один раз открыть HTTPS-ссылку с интернетом, дождаться сообщения «Готово к работе без интернета», закрыть вкладку, отключить интернет и снова открыть ту же ссылку. Приложение должно загрузиться и работать, включая создание, отметки, перенос, каталог и историю.

Для этого `sw.js` устанавливает версионированный кэш всех файлов интерфейса. Успешная установка — только после загрузки полного набора. Кэшировать HTML, CSS, основной JS, манифест и обе иконки. Для собственных ресурсов использовать cache-first; при отсутствии записи получить с сети и сохранить только корректный ответ. Для навигации внутри scope при недоступной сети вернуть закэшированный `index.html`. Не перехватывать сторонние URL и запросы вне scope; не кэшировать неуспешные ответы.

Service worker находится рядом с `index.html`, регистрируется с относительным путём и областью этой папки. Локальные ресурсы разрешать относительно базового URL worker, а не относительно произвольного URL навигации. Пользовательские данные читаются/пишутся основным JS, не service worker.

Показывать состояния готовности: «Подготавливаем работу без интернета», «Готово к работе без интернета», при ошибке — «Не удалось подготовить офлайн-режим. Подключитесь к интернету и попробуйте снова» с действием повтора. Готовность определять по установленному полному кэшу и активному контролирующему worker, а не только по наличию `navigator.serviceWorker` или `navigator.onLine`. При неподдерживаемом API приложение работает онлайн и предупреждает об отсутствии повторного офлайн-запуска.

При потере сети показывать ненавязчивое «Нет подключения к интернету». В подготовленном приложении это не блокирует действия. Показатель подключения приблизительный и не заменяет обработку ошибок загрузки файлов.

При новой версии менять имя кэша и содержимое worker. Новую версию полностью установить в отдельный кэш; не заменять часть ресурсов текущей страницы. Обновление ожидает закрытия старых вкладок, без принудительного `skipWaiting()` и перезагрузки во время ввода. Показать «Обновление готово. Закройте все вкладки планировщика и откройте его снова». При активации удалять только старые кэши с собственным префиксом `shopping-planner-app-`; не очищать localStorage и чужие кэши. При неудачной установке обновления рабочая старая версия сохраняется.

Первое посещение без сети до установки кэша не поддерживается. Браузер может удалить локальные данные и кэш; приватный режим, очистка браузера или смена устройства/браузера не гарантируют сохранность. На странице в краткой справке указать: «Данные хранятся только в этом браузере. Очистка данных сайта удалит списки. Для офлайн-запуска сначала дождитесь сообщения о готовности». Не обещать бессрочную сохранность или синхронизацию.

### 12.1. Помощь с установкой на телефон

Установка — удобный способ открытия, а не условие офлайн-работы. Справка «Как добавить на главный экран» доступна из всех трёх разделов в режиме обычного браузера. Для iPhone в Safari объяснить: открыть меню «Поделиться», выбрать «На экран Домой» и подтвердить; для остальных браузеров предложить пункт «Установить приложение» или «Добавить на главный экран», если он доступен. Названия и расположение пунктов могут зависеть от браузера; не обещать наличие универсальной команды.

Если пришло `beforeinstallprompt`, вызвать `preventDefault()`, сохранить событие в памяти и показать кнопку «Установить на телефон» после готовности офлайн-кэша. Не вызывать системный диалог автоматически. По нажатию пользователя вызвать `prompt()` один раз для сохранённого события, обработать `userChoice`, затем очистить ссылку и скрыть кнопку независимо от принятия/отказа. При ошибке также очистить событие, показать справку и не блокировать покупки. Новое событие может снова сделать кнопку доступной; не сохранять его в localStorage.

При `appinstalled` скрыть кнопку. В standalone-режиме (`display-mode: standalone`, с резервной проверкой `navigator.standalone` для совместимых iOS-браузеров) не предлагать установку. Если событие не пришло, показывать только справку, а не неработающую кнопку. Отсутствие события не позволяет надёжно определить, установлен ли сайт в другом режиме. Отказ от установки не меняет данные и доступность приложения.

## 13. Интерфейс, доступность и безопасность

- Светлая тема, русские тексты, системный шрифт. Основной фон `#F6F7FB`, поверхности белые, основной текст `#172033`, акцент `#2563EB`, ошибки `#B91C1C`; реализатор проверяет контраст всех комбинаций, включая купленные товары.
- Адаптивность от 320 px без горизонтального скролла. На телефоне один столбец, на широком экране ограничить контент примерно 960 px. Длинные названия переносить, не перекрывать кнопки.
- Текст полей не менее 16 px, зоны нажатия не менее 44 × 44 px. Ничто не требует наведения мыши. Интерфейс учитывает экранную клавиатуру и безопасные области телефона.
- Использовать реальные кнопки, формы, подписи полей и чекбоксы. Название страницы «Планировщик покупок», `lang="ru"`, viewport для телефона, понятное сообщение при отключённом JS.
- Клавиатурная навигация, видимый фокус. Диалоги удерживают фокус, Escape отменяет, закрытие возвращает фокус к вызывающей кнопке. Нажатие по затемнению не подтверждает действие. Подтверждающие кнопки подписаны конкретно: «Удалить поход», «Перенести», «Завершить без переноса».
- Ошибки и сообщения доступны скринридеру через подходящие live-region; купленное различается чекбоксом и зачёркиванием, а не одним цветом. Сообщение об удалении доступно достаточно долго для отмены.
- Все пользовательские строки вставлять как текст через `textContent`/значения полей; пользовательский HTML не интерпретировать. Содержимое localStorage также считать недоверенным.
- Ключевые действия не зависят от анимаций; учитывать `prefers-reduced-motion`. Автоматическое перемещение фокуса не должно мешать отметкам покупок.
- Не спрашивать доступ к геолокации, уведомлениям, контактам или камере. Не отправлять названия товаров, историю и каталог во внешние сервисы.

## 14. Проверка и критерии приёмки

Проверить в доступных современных Chromium-браузерах и Safari на телефоне/эмуляции. Реальную проверку Android Chrome и iOS Safari указать отдельно от эмуляции; если устройство недоступно, честно отметить непроверенную платформу. Проверить ширины 320, 375, 768 и 1280 px, клавиатуру и длинные названия.

Обязательные проверки логики и ручные сценарии:

1. Чистое хранилище: нет демоданных; создаётся ровно один текущий поход. Повторное создание при существующем запрещено.
2. Названия с разным регистром/пробелами объединяются; разные единицы создают разные строки; повторное добавление снимает отметку. Сложение 0,1 + 0,2 даёт 0,3.
3. Пустые названия, 0, отрицательные значения, лишняя точность и недопустимые даты отвергаются без изменения данных. Значения на обеих границах допустимы; превышение суммы при объединении отклоняется полностью.
4. Отметки, зачёркивание, порядок, фильтры и счётчик работают и восстанавливаются после перезагрузки. Счётчик считает строки.
5. Редактирование сохраняет отметку без коллизии; подтверждённое объединение снимает её и не оставляет дубликат. Отмена всех форм ничего не меняет.
6. Удаление и отмена восстанавливают строку точно; после 10 секунд, следующего изменения или перезагрузки отмена недоступна.
7. Пример переноса: «Хлеб», 1 шт., куплен; «Молоко», 2 л., не куплено; «Яблоки», 0,5 кг, не куплено. После переноса в архиве только хлеб, новый текущий содержит молоко и яблоки без отметок. При повторной отправке второго похода не возникает.
8. При переносе без купленных архив пустой с числом перенесённых строк. Когда всё куплено, перенос недоступен. Источник завершён, второго текущего похода нет.
9. Завершение без переноса сохраняет некупленное в истории и предупреждает, что перенести позже нельзя. Архив недоступен для редактирования. Удаление и очистка истории не затрагивают каталог и текущий поход.
10. Все введённые названия появляются в каталоге; удалённое название не возвращается после запуска/отметки/переноса, но возвращается после нового добавления. Подсказки доступны с клавиатуры.
11. Перезапуск браузера восстанавливает текущий поход, историю, каталог и статусы; выбранный раздел и черновики не восстанавливаются.
12. Повреждённый JSON, неверная схема и несколько текущих походов не перезаписываются автоматически. Явный сброс удаляет только ключ приложения. Неизвестная версия защищена так же.
13. Смоделировать ошибку записи: интерфейс не показывает ложный успех; перенос не оставляет половину операции. В двух вкладках внешнее изменение блокирует устаревшую вкладку; только «Обновить данные» загружает актуальное состояние. Проверить также сброс ключа и расхождение при проверке перед записью, даже если событие storage ещё не обработано.
14. На HTTPS или localhost дождаться готовности, закрыть вкладку, отключить сеть, открыть заново. Все файлы загружаются, покупки доступны, действия сохраняются. При первом визите без сети успех не обещается.
15. Повторить офлайн-проверку при размещении в подпапке и при открытии URL папки/`index.html`. Проверить неудачную установку обновления: старая версия работает, данные не потеряны.
16. Новая версия применяется после закрытия старых вкладок, не во время редактирования; чужие кэши и ключи не удаляются.
17. Текст вроде `<img src=x onerror=alert(1)>` отображается буквально, без выполнения кода. В сети нет передачи данных покупок и внешних зависимостей.
18. Размер в истории включает весь JSON, не включает кэш и не изображается процентом квоты. При 2 МиБ возникает предупреждение, после уменьшения исчезает. Более 50 походов сохраняются без автоматического удаления. Смоделированное переполнение позволяет вручную удалить данные и повторить сохранение; не теряется черновик товара при переходе к очистке.
19. Установка: кнопка появляется только с сохранённым событием и готовым кэшем, открывает диалог только по нажатию и использует событие один раз. Отказ/ошибка не меняют покупки. Без события доступна справка; standalone скрывает предложения. Проверить реальную установку на доступном устройстве отдельно от имитации событий.
20. migrateState для схемы 1 не изменяет данные и не вызывает лишнюю запись. Некорректная и неподдерживаемая версия не перезаписываются. При будущих миграциях проверить сохранность сущностей, ошибку преобразования/записи и отсутствие повторного преобразования после перезапуска.

Проверки чистых функций нормализации, количества, объединения, переноса и валидации состояния можно автоматизировать без фреймворка; браузерные сценарии и офлайн-проверки обязательны независимо от наличия автоматических тестов. Не заменять проверку закрытия/повторного открытия простым переключением сети в уже открытой вкладке.

## 16. Технические основания офлайн-архитектуры

Service worker поддерживает перехват загрузок и кэширование, работает в защищённом контексте HTTPS (localhost допустим для разработки) и не имеет доступа к `localStorage`. Поэтому он обслуживает файлы, а основной JS — пользовательские данные. Источник: [MDN — Service Worker API](https://developer.mozilla.org/en-US/docs/Web/API/Service_Worker_API).

`localStorage` привязан к источнику сайта и сохраняется между сеансами; его доступ может завершиться ошибкой, а поведение для `file://` не определено единообразно. Источник: [MDN — Window.localStorage](https://developer.mozilla.org/en-US/docs/Web/API/Window/localStorage).

Для Web Storage документация указывает ограничение до 5 МиБ localStorage на источник и необходимость обработки QuotaExceededError. Поэтому размер данных показывается как приблизительная оценка и не заменяет обработку ошибки записи. Источник: [MDN — квоты хранилищ](https://developer.mozilla.org/en-US/docs/Web/API/Storage_API/Storage_quotas_and_eviction_criteria).

`beforeinstallprompt` поддерживается не всеми браузерами; сохранённое событие используется для одного вызова системного предложения. При отсутствии события нужны инструкции для ручной установки. Источник: [web.dev — Installation prompt](https://web.dev/learn/pwa/installation-prompt).

## 17. Решения по замечаниям внешнего специалиста

| Замечание | Решение и причина |
| --- | --- |
| Ограничить историю 50 походами или показывать заполненность | Принять проблему и приблизительный индикатор размера с ранним предупреждением. Автоматическое удаление отклонить: число походов не определяет объём, а пользователь не просил терять историю. Ошибку квоты обрабатывать отдельно. |
| Добавить кнопку установки | Принять с проверкой доступности события и справкой для остальных браузеров. Это помогает открывать приложение на телефоне; установка не является условием работы без сети. |
| Подготовить миграцию схемы | Принять явный контракт, функцию-проверку и реестр будущих шагов. Пустая заглушка сама по себе не защищает данные; преобразование в ещё не определённую схему 2 не нужно. |
| Упростить синхронизацию вкладок | Принять: блокировка и ручное обновление вместо автоматической перестройки. Проверку актуальности перед записью сохранить, чтобы не перезаписать свежие данные. |
| Заменить отмену удаления корзиной или подтверждением | Отклонить: одна отмена и один таймер достаточно просты, а подтверждение каждого товара мешает быстрой работе. Корзина добавляет новую сущность и правила хранения. Таймер не сбрасывается при навигации; это явно уточнено. |
| Отказаться от целых тысячных и JS-валидации | Отклонить: точное сложение требует нескольких простых операций; единое правило применимо к добавлению и объединению. Браузерная валидация не заменяет проверку данных и единообразный приём запятой/точки. |
| Заменить массивы JSON хэш-таблицами | Отклонить как обязательную смену формата: для небольшого личного списка массивы проще, а поиск по названию всё равно требует отдельного индекса. Разрешить вычисляемые индексы в памяти без дублирования хранения. |
| Разделить текущий поход и историю на ключи | Отклонить: перенос затрагивает обе части; несколько setItem не образуют одну атомарную запись и потребуют дополнительного механизма восстановления. Одного документа достаточно для первой версии. |
| Сохранять activeTripId | Отклонить как поле JSON: это дублирует статус и добавляет инвариант согласованности. Разрешить вычисляемую ссылку на текущий поход в памяти. |
