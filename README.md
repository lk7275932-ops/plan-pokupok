# Планировщик покупок

Личный список покупок на русском языке: один текущий поход, отметки купленного, перенос остатка в следующий поход, каталог названий и история только для просмотра. Данные сохраняются в браузере через localStorage. После первой подготовки страницу можно закрывать и открывать снова без интернета.

Источник Pages — ветка main, каталог / (root). .nojekyll отключает обработку Jekyll; все ресурсы имеют относительные пути и поддерживают подпапку.

На Android откройте страницу в Chrome, дождитесь «Готово к работе без интернета», затем установите через кнопку или меню браузера. На другом домене localStorage отдельный: списки со старой ссылки Sites автоматически не переносятся.

## Размещение и запуск на телефоне

Передайте статическому хостингу следующие файлы с сохранением структуры:

```text
index.html
style.css
script.js
sw.js
manifest.webmanifest
icons/
  icon-192.png
  icon-512.png
```

Backend, база данных, сборка и установка зависимостей не нужны. README, тесты, `.git` и `.qa` не нужны для размещения. Хостинг должен выдавать страницу по HTTPS, `sw.js` как JavaScript, манифест как JSON-манифест и PNG как изображения. Размещать файлы вместе в корне сайта или одной подпапке. Не перенаправлять отсутствующие CSS/JS/PNG на HTML.

Откройте HTTPS-ссылку на телефоне с интернетом и дождитесь «Готово к работе без интернета». После этого можно закрыть вкладку, отключить сеть и открыть ту же ссылку снова. Если подготовка не удалась, подключитесь к интернету и нажмите «Повторить подготовку». Первый визит без сети не поддерживается.

На Android используйте «Установить на телефон», когда браузер предоставит эту возможность, или соответствующий пункт меню браузера. В Safari на iPhone: «Поделиться» → «На экран Домой». Подсказка доступна в приложении. Установка не является условием работы без сети. Наличие системной команды и её название зависят от браузера; собственный APK не создаётся.

Готовность означает активный service worker и полный кэш интерфейса, а не просто наличие подключения. Браузер может удалить кэш и данные; после очистки сайта подготовку необходимо выполнить заново.

В приватном режиме данные и кэш могут удаляться после закрытия приватных окон. Для постоянного использования открывайте приложение в обычном профиле браузера.

## Локальная разработка

Для проверки на компьютере, где установлен Node.js:

```text
node tests/serve.cjs
```

Откройте `http://127.0.0.1:4173/`. Localhost позволяет проверять service worker. Сервер привязан только к компьютеру: эта ссылка не открывает приложение на другом телефоне. Для телефона нужен статический HTTPS-хостинг.

`tests/serve.cjs` — служебный сервер QA с тестовой подпапкой `/nested/` и управлением имитацией неисправностей. Он не используется в продукте и не должен запускаться как публичный сервер. Открытие `index.html` двойным щелчком показывает пояснение о HTTPS; оно не заменяет офлайн-запуск по ссылке.

## Данные и ограничения

Данные находятся в ключе `shopping-planner.state.v1`: единый JSON со схемой версии 1, походами и каталогом. Они не отправляются на сервер и не синхронизируются с другими устройствами или браузерами. Очистка данных сайта удаляет покупки; резервное копирование и импорт/экспорт в первую версию не входят.

В истории показан приблизительный размер всех данных. От 2 МиБ появляется раннее предупреждение; это не процент фактической квоты. При переполнении можно удалить ненужные походы или названия и повторить сохранение; несохранённую покупку можно вернуть после очистки. Автоматического удаления старых походов нет.

Повреждённые данные и неподдерживаемая версия не перезаписываются. Можно повторить чтение или явно сбросить собственные данные с подтверждением. Если данные изменились в другой вкладке, приложение требует «Обновить данные», предупреждая об отбрасывании несохранённого ввода. Одновременные транзакции между вкладками не реализованы.

Количество поддерживает ручной ввод и кнопки ▲/▼ внутри поля; кнопки меняют его на 1, сохраняют дробную часть и не выходят за границы. Автоматическое название «Покупки — дата» меняется вместе с датой; собственное название сохраняется.

## Обновление приложения и схемы

При изменении HTML, CSS, JS, манифеста или иконок изменить `VERSION` в `sw.js` (сейчас `v3`), выполнить `node tests/update-cache-hashes.cjs`, затем `node --test tests/cache-integrity.test.cjs` и разместить полный комплект файлов. Это инструменты сопровождающего проект; для запуска пользователю сборка и Node.js не нужны. Хостинг должен отдавать исходные файлы без минификации или иных преобразований содержимого; `.gitattributes` закрепляет LF для файлов выпуска, чтобы Git не менял их байты. Для проверки/доставки нового комплекта использовать согласованную публикацию всех файлов, чтобы не выдавать половину обновления. Браузер готовит отдельный кэш; новая версия ждёт закрытия всех прежних вкладок. Приложение сообщает об этом и не перезагружает страницу во время ввода. При неудачном обновлении старая версия продолжает работать. SHA-256 связывает каждый ресурс с выпуском: повреждённый кэш восстанавливается только подходящими файлами. Если сервер уже выдаёт новый выпуск, старая версия отклоняет несовместимый ответ и повторную подготовку; следует закрыть все вкладки и открыть приложение снова после установки нового комплекта. Ошибка CacheStorage не препятствует онлайн-запуску с подходящими сетевыми файлами, но отключает сообщение об офлайн-готовности. Активированная версия очищает старые кэши только своей папки, сохраняя чужие кэши и localStorage.

Не переименовывать ключ localStorage вслед за номером схемы. Для будущей версии данных добавить шаги в реестр `MIGRATIONS`, валидаторы входа/выхода и тесты по контракту ТЗ. Преобразования выполняются на копии в памяти, запись — одна, после проверки актуальности и полной валидации. При ошибке исходная строка остаётся нетронутой. Сейчас схема 1 читается без миграции; схемы 2 ещё нет и её поддержка не заявляется.

## Фактически выполненные проверки

Проверка на Windows в Chromium 155.0.8059.40 через Playwright; отдельный постоянный профиль Microsoft Edge использовался для настоящего перезапуска браузера. Мобильные размеры — 320, 375, 768 и 1280 px. Это не проверка реального Android/iPhone или Safari.

- 48 тестов логики и целостности выпуска прошли (включая SHA-256 шести файлов): нормализация, числа, даты, объединение, перенос, история, схема/версия и оценка размера.
- 279 браузерных утверждений прошли во всех основных сценариях, включая дополнения про количество и дату. Количество включает повторные проверки фокуса и размеров.
- Закрытие и повторное открытие без сети проверены для `/`, `/index.html`, `/nested/`, `/nested/index.html`. В офлайн-режиме работали добавление, каталог, отметки, перенос, история и сохранение.
- Полный перезапуск Edge с тем же профилем и отключённой сетью восстановил идентичный JSON и кэш; новое добавление офлайн сохранилось. Сеть отключалась средствами браузерного контекста; физическое выключение Wi-Fi телефона не проверялось.
- Проверены полный и повреждённый кэш, повтор подготовки, недоступный ресурс, неудачное/успешное обновление, ожидание закрытия вкладок, сохранность данных и чужих кэшей.
- Проверены запреты чтения/записи, переполнение, повреждение, сброс и две вкладки. Ошибки хранилища имитировались в тестовом контексте; большой JSON с 65 архивами действительно записан и прочитан.
- Проверены манифест браузерным API и PNG 192 × 192 / 512 × 512, доступность справки, отсутствие внешних ресурсов, безопасность текстового вывода, отсутствие JS, отсутствие service worker API и ограничение `file://`.
- В постоянном профиле Edge получено настоящее событие установки, требований установки браузер не счёл нарушенными, системное предложение вызвано кнопкой. Подтверждённое завершение установки в ОС в безоконном режиме не получено. Остальные ветви установки — отказ, ошибка, однократный вызов, задержка до готовности, standalone — проверены имитацией событий. Имитация не объявляется реальной установкой.

Тесты логики:

```text
node --test tests/step1-core.test.cjs tests/step2-core.test.cjs tests/step3-core.test.cjs tests/cache-integrity.test.cjs
```

Файлы `tests/*.check.js` содержат функции для Playwright Page. Перед их выполнением нужен сервер выше; эти функции запускались браузерным инструментом Playwright. Основные сценарии изолируют данные и закрывают контексты. Проверка перезапуска создаёт отдельный профиль в `.qa`. Для повторного запуска вне текущего окружения изменить абсолютные пути снимков/профиля и путь к Edge под свою систему; зависимости тестирования не нужны пользователю приложения.

## Исправление запуска установленного приложения

Sites перенаправляет index.html на URL папки. Worker v3 сохраняет проверенный ответ без признака redirected, чтобы Chrome мог использовать его при офлайн-навигации. Кэш и списки автоматически не сбрасываются. Для применения обновления полностью закрыть установленное приложение и все вкладки планировщика, открыть HTTPS-ссылку в Chrome с интернетом и дождаться готовности; после сообщения о новом выпуске ещё раз закрыть все окна и открыть приложение.

Дополнительно прошли 6 проверок перенаправленного ответа на локальном сервере (корень/подпапка), 5 проверок реального опубликованного сайта: полный кэш, перезагрузка и новая вкладка без сети, сохранность JSON и добавление офлайн. Это браузерная автоматизация с мобильным размером, не реальный запуск с Android-значка.

## Исправления после сверки с ТЗ

Все пять обнаруженных расхождений исправлены. `tests/audit-regression.check.js` проверяет отказы открытия/записи CacheStorage, отказ несогласованного выпуска и восстановления старого кэша новыми файлами, переход к очистке из подтверждения объединения с сохранением черновика, пустые фильтры и доступные сообщения об ошибках (22 утверждения). Ошибки полей имеют постоянные live regions с `aria-live="polite"`, `aria-atomic="true"` и связью с полем. Фактическое озвучивание экранным диктором требует ручной проверки.
